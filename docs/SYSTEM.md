# Устройство приставки

Описание компонентов, их связей и того, где что лежит. Приставка — обычный
компьютер Debian с автовходом в графическую сессию и набором служб, которые
делают из него телевизионную приставку.

## Состав

| Служба | Роль | Файлы |
|---|---|---|
| `stb-wifi-remote` | приёмник кнопок с телефона: отвечает на поиск в сети и принимает соединение на порту 3000, представляясь телевизором LG | конфиг, `buttons-wifi.conf`, журнал `faketv.log` |
| `stb-watch` | вся фоновая работа одной программой, девять разделов: `tv`, `app`, `audio`, `wol`, `chassis`, `bt-agent`, `bt-keys`, `bt-pointer`, `bt-log` | `stb.conf`, `buttons-bt.conf`, журналы |
| `stb-tv-boot` | разовый хук при загрузке: если телевизор уже включён, поднять интерфейс | — |
| `stb-tv-shutdown` | разовый хук при выключении приставки: погасить телевизор | — |
| `stb-nic-tune` | разовая настройка сетевого чипа при загрузке | — |
| `stb-nic-watch` (таймер 2 мин) | следит за зависаниями сетевого чипа, при признаках сбрасывает линк | — |
| `stb-screensaver` | гасит экран после простоя в режиме приставки; любое нажатие возвращает картинку | `stb.conf`, `stb-screensaver` |
| `stb-web` (пользовательская) | страница с плитками на `127.0.0.1:8090` и выполнение команд плиток | `tiles.json` |
| `stb-browser` (пользовательская) | браузер в полноэкранном окне, открывает страницу с плитками | профиль браузера |

Системные службы собраны под целью `stb.target`: `systemctl restart stb.target`
перезапускает весь набор. Пользовательские (`stb-web`, `stb-browser`) живут в
сессии пользователя; для них есть `stb ctl` (см. «Проверка состояния»).

## Поток нажатия

```
телефон
  ├─ Wi-Fi ──> stb-wifi-remote ──┐
  └─ Bluetooth ─> xbindkeys ─────┴──> stb key <действие> ──> приставка (XTest)
                                                                └─> телевизор (webOS)
```

Карта кнопок переводит название кнопки в действие. Действие решает, что делать,
по текущему режиму: `nuc` — управляем приставкой, `tv` — телевизором.

## Настройки

```
/opt/stb/config/stb.conf            все параметры: адреса, имена, пороги
/opt/stb/config/buttons-wifi.conf   карта кнопок Wi-Fi
/opt/stb/config/buttons-bt.conf     карта кнопок Bluetooth
/opt/stb/config/tiles.json          плитки на экране
/etc/stb/config                     ссылка на stb.conf
```

Применение правок:

| Что правили | Команда |
|---|---|
| карту Wi-Fi | `sudo /opt/stb/bin/stb keys apply wifi` |
| карту Bluetooth | `sudo /opt/stb/bin/stb keys apply bt` |
| `stb.conf` | перезапустить затронутую службу |
| `tiles.json` | ничего: страница перечитывает его раз в минуту |

Сторож простоя (`stb screensaver`) читает два порога: `SCREENSAVER_MINUTES`
— когда открыть чёрную вкладку, `STB_TV_SLEEP_AFTER` — через сколько минут после
этого послать телевизору выключение. Второй шаг выполняется только в режиме
приставки и только если телевизор действительно включён; отметка «уже погасили»
лежит в `/run/user/1000/stb-tv-slept` и снимается при закрытии заставки. После
выключения телевизора работает обычная цепочка `stb-watch` (раздел `tv`): гашение картинки
сразу, выключение приставки — по `IDLE_POWEROFF_AFTER`.

### Уход из приложения и таймер

Приложение уходит с экрана двойным Back (см. «Back и Home в окне приложения»):
окно снимается, процесс живёт, возврат по плитке мгновенный, а не холодным
стартом. Отметка о скрытии лежит в `/run/user/1000/stb-app-hidden`; её файл
хранит заголовок окна, время — mtime.

Если приложение скрыто дольше `APP_HIDE_MINUTES` (по умолчанию 10), сторож
(раздел `app` в `stb-watch`) гасит его целиком: `flatpak kill` для плеера,
закрытие окна — для остальных. Вернулись раньше — плитка показывает окно,
снимает отметку и поднимает звук (`pipewire` мог быть погашен лёгким режимом).

Запуск ждёт окно 20 секунд — столько же, сколько ждёт приложение-пульт; иначе
пользователь видит ошибку раньше, чем приставка сдаётся. Если окно не появилось,
остатки гасятся, чтобы следующая попытка не упиралась в «живой, но без окна»
flatpak-экземпляр: `flatpak run` при таком экземпляре не создаёт новое окно, а
«активирует» старое.

### Приёмник пульта и кнопка Back

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `GESTURES` | `BACK` | кнопки с выдержкой. Для них двойное нажатие — отдельное событие (`<кнопка>-double` в диспетчере), а одиночное ждёт окно. Кнопки, которых здесь нет, идут сразу |
| `DUP_GAP` | `0.1` | две одинаковые кнопки ближе этого — одно нажатие |
| `DUP_BACK` | `0.1` | то же для Back: второй Back — команда, а не дубль, поэтому у него своя склейка |
| `DOUBLE_BACK` | `1.0` | окно второго нажатия Back; столько же ждёт одиночное, прежде чем уйти |
| `STB_LOG_RAW` | `0` | писать в журнал сырые сообщения кнопок (для разбора пульта) |

Замерено на живом пульте: два Back с интервалом от 0,10 до 0,80 с возвращают на
приставку; ближе 0,08 с события склеиваются в одно нажатие. Приложение присылает
одно сообщение на одно нажатие — «двойных» сообщений у него нет.

### Состояние телевизора

Сторож решает по трём правилам:

1. состояние известно (`Active`, `Suspend`, `Screen Off`) — включён только `Active`;
2. состояние неизвестно, но телевизор отвечает в сети — экран **не трогаем**
   (иначе чёрный экран при живом телевизоре);
3. состояние неизвестно и телевизор ушёл из сети — это ждущий режим (этот LG
   в standby сеть гасит). Экран гасим только со второй такой проверки подряд.

`STB_TV_STATE_MAX_AGE` (по умолчанию 90 с) — возраст сведений, после которого
они считаются устаревшими. Проверяется пингом: если телевизора нет в сети,
вопрос к демону не задаётся вовсе — иначе каждый опрос ждал бы 5 секунд.

### Одно соединение с телевизором

У LG ограничено число одновременных подключений. Демон держит **ровно одно**:
неудачные подписки (`subscribe_power` и остальные на этой модели не работают)
оставляли полуоткрытые сокеты, и Home Assistant перестал помещаться в лимит —
его интеграция выглядела «загруженной», но сущность навсегда оставалась `off`.

Проверка: `ss -tn | grep <адрес телевизора>` — от нашего процесса должен быть
один сокет. Если HA «не видит» телевизор: сначала проверить число соединений,
затем пересоздать интеграцию в HA (перезагрузка записи не помогает).

### Кэш браузера

Профиль Firefox ограничен 256 МБ (`user.js`: `browser.cache.disk.capacity`).
Гигабайт кэша на медленном диске — это 20–30 секунд до появления окна, а всё
это время на телевизоре чёрный экран с курсором. Страховка в службе браузера:
если `cache2` больше 400 МБ при запуске, он удаляется.

## Сеть

Приставка стоит между домашней сетью и телевизором: телевизор подключён
проводом в отдельный порт приставки и выходит в сеть через неё.

- порт в телевизор — отдельный интерфейс со своим адресом, телевизор получает адрес из той же подсети;
- на обоих интерфейсах должен быть включён `proxy_arp` — **по интерфейсам**, общей настройкой
  он не раздаётся, и без этого телевизор пропадает из сети после перезагрузки
  (`/etc/sysctl.d/90-tv-proxyarp.conf`);
- чип Intel `e1000e` под нагрузкой склонен к зависанию; признак — пульт молчит и
  телевизор не отвечает по сети; лечится сбросом линка (`ip link set … down/up`),
  чем и занимается `stb-nic-watch`;
- пакет пробуждения, пришедший на беспроводной адрес телевизора, пересобирается на
  проводной адрес: адрес получателя записан внутри пакета, простой пересылкой байтов
  дело не решается.

## Графическая сессия

Автовход пользователя, оконный менеджер openbox, окно браузера без рамки и
развёрнутое на весь экран. Курсор увеличенного размера (тема Adwaita, 64) и
всегда видим: `unclutter` убран, он прятал указатель и в приложениях, из-за чего
нельзя было целиться.

Чутьё точпада — `POINTER_SPEED` (0.35): приложение присылает движение редкими
крупными шагами, без множителя указатель улетал в угол экрана за один кадр.
Клик сначала применяет накопленное движение, иначе нажатие уходило по старому
месту.

## Правки вне `/opt/stb`

Помимо каталога приставки система требует нескольких файлов. Копии всех них лежат
в `/opt/stb/system` — пути внутри повторяют настоящие, поэтому установка сводится
к копированию дерева в корень (`README.md` рядом).

| путь | зачем |
|---|---|
| `/etc/systemd/system/stb.target` | единая цель комплекса: `stb-tv-link`, `stb-watch`, `stb-wifi-remote` и остальные юниты с `PartOf=stb.target` — старт и перезапуск одной командой |
| `/etc/systemd/system/stb-nic-tune.service` | `ethtool` для чипа `e1000e`: tso/gso off, eee off, rx 512, wol gub |
| `/etc/systemd/system/stb-nic-watch.service`, `.timer` | проверка зависаний сетевого чипа каждые две минуты |
| `/etc/systemd/system/stb-watch.service` | одна программа на все разделы: телевизор, скрытое приложение, звук, WoL, кнопка корпуса, Bluetooth-пульт |
| `/etc/systemd/system/stb-tv-boot.service` | при загрузке включает телевизор и вход приставки |
| `/etc/tmpfiles.d/stb.conf` | каталог `/run/stb` (0775, пользователь приставки): режим, флаги, состояние телевизора |
| `/etc/sysctl.d/90-tv-proxyarp.conf` | `ip_forward` и `proxy_arp` по интерфейсам |
| `/etc/systemd/logind.conf.d/10-powerkey.conf` | кнопка корпуса: короткое нажатие игнорируется, долгое — выключение |
| `/etc/lightdm/lightdm.conf.d/50-stb.conf` | автовход пользователя приставки, сессия `stb` |
| `/etc/bluetooth/main.conf` | имя `home-tvbox1-bt`, `FastConnectable = true` |
| `/etc/NetworkManager/conf.d/wifi-no-rand-mac.conf` | без случайного MAC при сканировании сети |
| `/etc/stb/config` | символическая ссылка на `/opt/stb/config/stb.conf` |
| `/usr/local/bin/tv` | символическая ссылка на `/opt/stb/bin/stb`: запуск под именем `tv` программа считает сокращением `stb tv` |

Службы пользователя (`stb-browser`, `stb-web`, `stb-screensaver`) лежат не здесь,
а в `~/.config/systemd/user` — их копии в `home/`.

## Связь с телевизором

Телевизором управляет один демон — `stb-tv-link`. Он держит **одно**
постоянное соединение (SSAP) и подписки на состояние питания, выход звука и
текущее приложение; остальные части приставки спрашивают его через сокет
`/run/stb/tv.sock`:

| кто | зачем |
|---|---|
| `stb-wifi-remote` | кнопки, указатель и клики приложения-пульта |
| `stb-watch` (`bt-pointer`) | указатель и кнопки Bluetooth-пульта |
| `stb-watch` (`tv`, `audio`) | состояние питания для гашения и выключения, выход звука |
| `stb`, `stb key` | команды из командной строки и от кнопок |

### Протокол `stb-tv-link`

Сокет `/run/stb/tv.sock`, обмен — одна JSON-строка на запрос, ответ — одна
JSON-строка. Клиент (библиотека `lib/stbtv.py`, класс `TvDaemon`) ждёт ответ
8 секунд на всю операцию; демон тратит на команду один бюджет — 5 секунд
вместе с ожиданием очереди и подключением к телевизору, плюс до 1 секунды на
закрытие зависшего соединения. Итого худший случай около 6 секунд, и клиенту
остаётся запас на ответ (раньше этапы считались независимо: 6 + 5 + 6 = 17 с,
и клиент сдавался задолго до конца работы).

Когда срок вышел, демон отказывает сразу, без «минимального остатка» в десятые
доли секунды: иначе несколько этапов подряд могли бы выйти за срок. Соединение
сначала отсоединяется, а потом закрывается — зависшее закрытие не оставляет
демон со старым клиентом, и следующий запрос поднимает новое. Неудачное или
отменённое подключение тоже закрывает свой клиент (отдельной задачей: в
отменённой корутине ждать уже нельзя), иначе на каждый сбой оставался бы
открытый сокет.
Клиентский срок намеренно больше бюджета: демон обязан успеть сказать «не
вышло» раньше, чем клиент решит, что демон мёртв и полезет напрямую.

| команда | обязательные поля | что делает |
|---|---|---|
| `state` | — | питание, выход звука, приложение, громкость, mute |
| `key` | `name` | нажатие кнопки: `UP`, `ENTER`, `BACK`, `VOLUMEUP`… |
| `vol` | `level` **или** `dir` | `level` 0–100 — задать громкость; `dir: down` — шаг вниз; иначе шаг вверх |
| `mute` | `on` **или** `state` | включить/выключить звук: `true/false`, `on/off` |
| `input` | `id` | выбрать вход, например `HDMI_3` |
| `app` | `id` | запустить приложение по идентификатору |
| `speaker` | `id` | переключить выход звука |
| `speakers` | — | список выходов звука |
| `power` | `on`/`state` | выключить телевизор; включение — только WoL |
| `move` | `dx`, `dy` | сдвинуть указатель |
| `click` | — | клик |
| `scroll` | `dy` | прокрутка |
| `apps` | — | все приложения телевизора |

Команды выполняются по одной: на телевизор у демона один клиент, и
параллельные запросы на этой модели приводили к обрывам. Команда и ожидание
очереди ограничены 5 секундами, так что зависший запрос не блокирует пульт
навсегда; периодическое обновление звука — 5 секундами на запрос и 2 секундами
на очередь (не дождалось — тик пропускается).

Ответ всегда содержит `ok`. Отказ телевизора — `{"ok": false, "msg": "..."}`;
недоступность самого демона добавляет `"transport": true`. Это различие
принципиально: прямое подключение библиотекой (`bscpylgtv`) разрешено только
при `transport` и только если служба `stb-tv-link` не запущена. Повторять
команду вторым соединением при отказе телевизора нельзя — ломается
единственное SSAP-подключение и нажатие может сработать дважды.

Состояние хранится в памяти демона. Подписок на события нет (`states=[]`):
на этой модели они рвали соединение, поэтому состояние берётся опросом.

Отметки времени — по каждому полю: `power_updated`, `sound_updated`,
`app_updated`. Ответ на вопрос о звуке не делает свежим устаревшее питание;
раньше был один `updated`, и этого хватало, чтобы гасить экран по старым
данным. `updated` — общая отметка активности: он двигается и после команд (`key`,
`vol`, `mute`, `input`, `app`). Для решений о питании он не используется:
сторож смотрит только на `power_updated`, иначе оптимистичное состояние после
команды выключения выглядело бы как подтверждение телевизора. Ответ содержит `ages` — возраст каждого поля в
секундах; `null` значит «ни разу не подтверждалось».

Сторож ходит к демону тем же клиентом `lib/stbtv.py`, что и остальные части:
своего сокет-кода в `stb-watch` больше нет. Срок запроса — те же 8 с; опрос идёт
каждые 4 секунды, поэтому медленный ответ может растянуть один тик.
Это осознанно: если телевизор не отвечает по сети, SSAP вообще не спрашивается
(сначала ping), а при живом телевизоре лучше подождать ответ, чем решить
«выключен» по догадке. Решение принимается по двум одинаковым ответам подряд.

Сторож принимает решения по `power` и его отметке. Если приложение на
телевизоре неизвестно (демон молчит), `tv_shows_own_app()` отвечает «не знаю»:
отсчёт простоя в этом случае не сбрасывается и телевизор не гасится.

### Back и Home в окне приложения

Две кнопки — два разных намерения:

- Одиночный Back уходит в приложение (у плеера и браузера своя навигация).
  Отправка ждёт окно `DOUBLE_BACK` — иначе нельзя понять, что второго нажатия
  не будет.
- Двойной Back в том же окне — «я вернусь»: придержанное одиночное нажатие
  отменяется и в приложение не уходит, поэтому место в нём сохраняется; окно
  прячется, процесс живёт, ставится отметка.
- Home в окне приложения — «я закончил»: приложение закрывается совсем (для
  плеера — flatpak kill), отметка снимается, на экране сетка. Home закрывает и
  уже скрытое приложение, иначе после Back+Home оставался бы висящий процесс.
- Home на сетке — уборка: закрываются все приложения и лишние окна, сетка
  показывается заново. Вкладки не пересчитываются и не закрываются: с тех пор
  как заставка перестала открывать новую вкладку, их и не появляется. Если
  понадобится полная чистка, есть плитка «Перезапуск интерфейса» — она
  перезапускает окно браузера (около 3 секунд) и открывает одну вкладку с сеткой.


### Когда сторож не трогает экран

Сторож поднимает наш интерфейс только при настоящем включении телевизора:
до этого он должен был сам сообщить, что спит (`Standby`, `Screen Off`,
`Active Standby`), и пропасть из сети. Молчание SSAP при телевизоре, который
отвечает в сети, — это сбой связи, а не включение. Первый опрос после запуска
сторожа тоже ничего не переключает, а при открытом приложении не сбивается
и вход телевизора. Раньше сетка вылезала поверх фильма на ровном месте.

### Выключение приставки и телевизор

`stb poweroff` сначала гасит телевизор и ждёт подтверждения (до 20 секунд, обычно
1–3), и только потом выключает приставку. Иначе телевизор, оставшись включённым,
поднимает приставку обратно через WoL — это и случилось ночью 25.11.2026.
Если телевизор не подтвердил выключение, приставка всё равно выключается, а в
журнал пишется, что подтверждения не было.
`--keep-tv` — выключить только приставку, телевизор оставить;
`--dry-run` — прогнать порядок, не выключая приставку.

### Кнопка «Телевизор»

Плитка будит телевизор, открывает то, что смотрели последним, и переводит пульт
в режим телевизора. «Оставить источник как есть» здесь не работает: после
возврата в сетку источник — наш вход, и плитка показывала бы ту же сетку.

Что запоминается: сторож каждые несколько секунд спрашивает у демона текущее
приложение телевизора и, если это не наш вход, пишет его в `/var/lib/stb/tv-last`.
Поэтому помнятся и переключения, сделанные пультом самого телевизора. Если
запомненного ещё нет — открывается `TV_FALLBACK_APP` (по умолчанию эфир).

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `TV_RESTORE_LAST` | `1` | `0` — не вспоминать и ничего не открывать |
| `TV_FALLBACK_APP` | `com.webos.app.livetv` | что открыть, если памяти ещё нет |
| `STB_TV_LAST` | `/var/lib/stb/tv-last` | файл памяти |

Список приложений телевизора: `stb tv getapps`; вход приставки — `TV_INPUT_ID`
(`HDMI_3`), менять его в коде не нужно.

### Звук и кнопки громкости

Звук приставки уходит в телевизор по HDMI (дальше ARC), поэтому `volup`,
`voldown` и `mute` **всегда** идут в телевизор, чем бы ни была занята приставка.

Заглушка приставки ставится и снимается по событиям, без опроса:

| Переход | Звук приставки |
|---|---|
| на сетку | выключен |
| запуск или показ Jellyfin | включён |
| плитка-сайт в новой вкладке (YouTube, Sonarr…) | включён |
| Home, скрытие приложения | выключен |
| эфир или Jellyfin на телевизоре | включён (звук даёт телевизор) |

Ручное управление — `stb sound on|off`; страница сетки перед переходом по ссылке
зовёт `/sound/on` на веб-сервере. Сторожей здесь нет намеренно: сторож спорил бы
с ручным выключением звука.

### Кнопки Play/Pause и OK в приложении

`playkey` и `pausekey` в приложении нажимают то, что под указателем. Причина:
кнопки OK на телефоне в режиме точпада нет, а Enter в Jellyfin нажимает прежний
фокус — фильм не открывался, зато открывалась карточка, которая была выбрана
раньше («попал в медиатеку»). На сетке эти кнопки запускают выбранную плитку.
В режиме телевизора уходят в телевизор как `PLAY`/`PAUSE`.

### SSDP: на что приставка отвечает

Приложение-пульт ищет телевизор несколькими запросами сразу, поэтому приставка
отвечает тем же типом, что спросили, — но только на те, которые действительно
изображает: webos-second-screen, MediaRenderer, DIAL и ssdp:all.
Поиск незнакомого типа пропускается и пишется в журнал приёмника: иначе
приставка обещала бы сервисы, которых у неё нет.

### Выбор входа поднимает телевизор

Проверено на 49UK6450: команда `set_input` (её посылает `stb live` и
переключение на приставку) выводит телевизор из ждущего режима. Поэтому
`stb live` включает телевизор, даже если он был выключен, а `stb mode nuc`
сам по себе — нет.

Нажатие проходит за 40–70 мс. Раньше каждая кнопка поднимала отдельный процесс
Python с WebSocket-рукопожатием — 0.5–1.5 с и постоянная нагрузка.
Если демон не отвечает, `tv` работает по-старому, напрямую.

## Модули

Приёмник пульта (`bin/stb-wifi-remote`) вынес всё, что можно проверить
отдельно, в библиотеку:

| модуль | что внутри |
|---|---|
| `lib/stbws.py` | кадры WebSocket: рукопожатие, сборка ответа, чтение от клиента. `read_ws_message()` склеивает фрагменты и переживает управляющий кадр (ping/pong) между ними; предел сообщения 1 МиБ, неожиданный кадр и продолжение без начала — ошибка протокола |
| `lib/stbtext.py` | буфер текста: кумулятивная диктовка, повторы, удаления |
| `lib/stbpointer.py` | указатель: копит движение, отправляет 25 раз в секунду |
| `lib/stbgesture.py` | кнопки с выдержкой: склейка повторов, придержка одиночного нажатия, двойное нажатие как отдельное событие |
| `lib/stbkeys.py` | таблица «кнопка → команда демона» для режима телевизора |
| `lib/stbtv.py` | клиент демона телевизора |
| `lib/stbtvlast.py` | память «что показывал телевизор»: записать чужое приложение, прочитать для плитки |
| `lib/stbx11.py` | указатель на экране через XTest, без запуска процессов |

В режиме телевизора кнопки идут прямо в демон (без `stb key`);
Power и возврат на приставку остаются в диспетчере — там нужна логика.

## Сторожа

Вся фоновая работа — одна программа `stb-watch` с девятью разделами:

| раздел | что делает | журнал |
|---|---|---|
| `tv` | состояние телевизора: включён — поднять интерфейс, выключен — погасить, долго выключен — выключить приставку | `tvwatch.log` |
| `app` | скрытое приложение: через `APP_HIDE_MINUTES` закрывает его совсем | `system.log` |
| `audio` | держит выход звука по настройке | `audio.log` |
| `wol` | повторяет пакеты пробуждения в провод телевизора | `wol.log` |
| `chassis` | кнопка на корпусе: короткое нажатие выключает приставку | `system.log` |
| `bt-agent` | сопряжение Bluetooth-пульта, только в открытом окне | `pair.log` |
| `bt-keys` | редкие клавиши пульта: раскладка, переключение режима | `extrakeys.log` |
| `bt-pointer` | тачпад пульта превращает в курсор телевизора | `pointer.log` |
| `bt-log` | журнал нажатий Bluetooth-пульта для диагностики | `buttons.log` |

`stb-watch all` поднимает все разделы потоками внутри одного процесса: падение
одного не мешает остальным, каждый поднимается сам. Для отладки любой раздел
запускается отдельно — `stb-watch tv`, `stb-watch bt-pointer` — и пишет в тот же
журнал.

Весь комплекс — три процесса: `stb-watch` (фоновая работа), `stb-tv-link`
(одно постоянное соединение с телевизором) и `stb-wifi-remote` (приёмник
пульта). Рядом живут пользовательские `stb-web`, `stb-browser` и сторож
заставки — они в графической сессии.

## Сборка дистрибутива

```sh
sudo /opt/stb/makedist.sh                    обновить system/ и home/ из живой системы
sudo /opt/stb/makedist.sh /tmp/stb.tar.gz    то же и упаковать
sudo /opt/stb/makedist.sh --to-misc          упаковать и положить на misc
```

Перед упаковкой прогоняются тесты и `install.sh --check`: если что-то красное,
архив не собирается.

Ключ доступа к телевизору (`~/.aiopylgtv.sqlite`) — секрет. В архив он **не
попадает**: после установки телевизор один раз спросит подтверждение. Нужен
готовый ключ в архиве — `--with-key`. В git он тоже не хранится (`.gitignore`).

## Тесты

Каталог `tests/` — pytest-набор без телевизора и X. Файлы собраны по темам:
демон (`test_daemon.py`), сторож (`test_watch.py`), отметки (`test_marks.py`),
формат журналов (`test_logs.py`), окна (`test_windows.py`), карты кнопок
(`test_buttons.py`), Back (`test_back_gate.py`), WebSocket (`test_ws.py`), ввод
текста (`test_tv_text.py`), приёмник (`test_fake_tv.py`), конфиг
(`test_config_vars.py`), плитки (`test_json_preprocess.py`), документы
(`test_docs.py`), качество исходников (`test_sources.py`), установщик
(`test_installer.py`).

Запуск: `sudo /opt/stb/tests/run_tests.sh` — pytest, затем pyflakes и
shellcheck. Правила написания тестов и карта файлов — `tests/README.md`.

`tests/fake_tv.py` — поддельный телевизор для ручных замеров;
`tests/bench_consumers.py` показывает на нём, сколько запросов, CPU и процессов
тратят сторожа.

## Журналы

```
/var/log/stb/faketv.log      что пришло от приложения-пульта по Wi-Fi
/var/log/stb/keys.log        какое действие выполнено и в каком режиме
/var/log/stb/buttons.log     нажатия Bluetooth-пульта (диагностика)
/var/log/stb/extrakeys.log   редкие клавиши пульта
/var/log/stb/pointer.log     указатель от пульта
/var/log/stb/pair.log        сопряжение Bluetooth
/var/log/stb/tv.log          команды телевизору
/var/log/stb/tvdaemon.log    постоянное соединение с телевизором
/var/log/stb/tvwatch.log     состояние телевизора, экономия, выключение
/var/log/stb/audio.log       выход звука
/var/log/stb/wol.log         пакеты пробуждения
/var/log/stb/screensaver.log заставка и гашение телевизора по простою
/var/log/stb/idle.log        гашение и подъём интерфейса
/var/log/stb/session.log     графическая сессия
/var/log/stb/system.log      запуск и падения разделов stb-watch, кнопка корпуса
```

Отметка времени одна на все журналы: `дата время`. В `keys.log` добавляются
миллисекунды и режим — `2026-11-25 12:03:41.207 [nuc] back → приложению`:
по этому журналу меряют темп двойных нажатий. Формат закреплён тестом
`tests/test_logs.py`.

## Проверка состояния

```sh
sudo stb ctl status     # таблица служб: запущена, включена
cat /run/stb/mode                    # текущий режим: nuc или tv
tail -5 /var/log/stb/keys.log        # последние нажатия
```

## Управление без клавиатуры

Если графическая сессия работает, ввод можно подать в активное окно.

```sh
E='env DISPLAY=:0 XAUTHORITY=/home/USER/.Xauthority HOME=/home/USER'

sudo -u USER $E xdotool type --delay 60 'текст'   # напечатать
sudo -u USER $E xdotool key Return                # нажать клавишу
sudo -u USER $E xdotool mousemove 960 620 click 1 # клик по координатам
sudo -u USER $E xdotool getactivewindow getwindowname  # что в фокусе
```
