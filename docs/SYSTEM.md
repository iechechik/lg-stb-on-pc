# Устройство приставки

Описание компонентов, их связей и того, где что лежит. Приставка — обычный
компьютер Debian с автовходом в графическую сессию и набором служб, которые
делают из него телевизионную приставку.

## Состав

| Служба | Роль | Файлы |
|---|---|---|
| `stb-wifi-remote` | приёмник кнопок с телефона: отвечает на поиск в сети и принимает соединение на порту 3000, представляясь телевизором LG | конфиг, `buttons-wifi.conf`, журнал `faketv.log` |
| `stb-watch` | вся фоновая работа одной программой, восемь разделов: `tv`, `audio`, `wol`, `chassis`, `bt-agent`, `bt-keys`, `bt-pointer`, `bt-log` | `stb.conf`, `buttons-bt.conf`, журналы |
| `stb-tv-boot` | разовый хук при загрузке: если телевизор уже включён, поднять интерфейс | — |
| `stb-tv-shutdown` | разовый хук при выключении приставки: погасить телевизор | — |
| `stb-nic-tune` | разовая настройка сетевого чипа при загрузке | — |
| `stb-nic-watch` (таймер 2 мин) | следит за зависаниями сетевого чипа, при признаках сбрасывает линк | — |
| `stb-screensaver` | гасит экран после простоя в режиме приставки; любое нажатие возвращает картинку | `stb.conf`, `stb-screensaver` |
| `stb-web` (пользовательская) | страница с плитками на `127.0.0.1:8090` и выполнение команд плиток | `tiles.json` |
| `stb-browser` (пользовательская) | браузер в полноэкранном окне, открывает страницу с плитками | профиль браузера |

Системные службы собраны под целью `stb.target`: `systemctl restart stb.target`
перезапускает весь набор. Пользовательские (`stb-web`, `stb-browser`) живут в
сессии пользователя; для них есть `stb ctl` (см. «Проверка состояния»).

## Поток нажатия

```
телефон
  ├─ Wi-Fi ──> stb-wifi-remote ──┐
  └─ Bluetooth ─> xbindkeys ─────┴──> stb key <действие> ──> приставка (XTest)
                                                                └─> телевизор (webOS)
```

Карта кнопок переводит название кнопки в действие. Действие решает, что делать,
по текущему режиму: `nuc` — управляем приставкой, `tv` — телевизором.

## Настройки

```
/opt/stb/config/stb.conf            все параметры: адреса, имена, пороги
/opt/stb/config/buttons-wifi.conf   карта кнопок Wi-Fi
/opt/stb/config/buttons-bt.conf     карта кнопок Bluetooth
/opt/stb/config/tiles.json          плитки на экране
/etc/stb/config                     ссылка на stb.conf
```

Применение правок:

| Что правили | Команда |
|---|---|
| карту Wi-Fi | `sudo /opt/stb/bin/stb keys apply wifi` |
| карту Bluetooth | `sudo /opt/stb/bin/stb keys apply bt` |
| `stb.conf` | перезапустить затронутую службу |

Сторож простоя (`stb screensaver`) читает два порога: `SCREENSAVER_MINUTES`
— когда открыть чёрную вкладку, `STB_TV_SLEEP_AFTER` — через сколько минут после
этого послать телевизору выключение. Второй шаг выполняется только в режиме
приставки и только если телевизор действительно включён; отметка «уже погасили»
лежит в `/run/user/1000/stb-tv-slept` и снимается при закрытии заставки. После
выключения телевизора работает обычная цепочка `stb-watch` (раздел `tv`): гашение картинки
сразу, выключение приставки — по `IDLE_POWEROFF_AFTER`.
| `tiles.json` | ничего: страница перечитывает его раз в минуту |

### Приёмник пульта и кнопка Back

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `DUP_GAP` | `0.1` | две одинаковые кнопки ближе этого — одно нажатие |
| `BACK_DUP_GAP` | `0.1` | то же для Back: у него своя склейка, общий фильтр его не трогает |
| `DOUBLE_BACK` | `1.0` | сколько ждём второй Back для возврата на приставку |
| `BACK_HOLD` | `1.0` | сколько одиночный Back ждёт перед отправкой в телевизор |
| `STB_LOG_RAW` | `0` | писать в журнал сырые сообщения кнопок (для разбора пульта) |

Замерено на живом пульте: два Back с интервалом от 0,10 до 0,80 с возвращают на
приставку; ближе 0,08 с события склеиваются в одно нажатие. Приложение присылает
одно сообщение на одно нажатие — «двойных» сообщений у него нет.

### Состояние телевизора

Сторож решает по трём правилам:

1. состояние известно (`Active`, `Suspend`, `Screen Off`) — включён только `Active`;
2. состояние неизвестно, но телевизор отвечает в сети — экран **не трогаем**
   (иначе чёрный экран при живом телевизоре);
3. состояние неизвестно и телевизор ушёл из сети — это ждущий режим (этот LG
   в standby сеть гасит). Экран гасим только со второй такой проверки подряд.

`STB_TV_STATE_MAX_AGE` (по умолчанию 90 с) — возраст сведений, после которого
они считаются устаревшими. Проверяется пингом: если телевизора нет в сети,
вопрос к демону не задаётся вовсе — иначе каждый опрос ждал бы 6 секунд.

### Одно соединение с телевизором

У LG ограничено число одновременных подключений. Демон держит **ровно одно**:
неудачные подписки (`subscribe_power` и остальные на этой модели не работают)
оставляли полуоткрытые сокеты, и Home Assistant перестал помещаться в лимит —
его интеграция выглядела «загруженной», но сущность навсегда оставалась `off`.

Проверка: `ss -tn | grep <адрес телевизора>` — от нашего процесса должен быть
один сокет. Если HA «не видит» телевизор: сначала проверить число соединений,
затем пересоздать интеграцию в HA (перезагрузка записи не помогает).

### Кэш браузера

Профиль Firefox ограничен 256 МБ (`user.js`: `browser.cache.disk.capacity`).
Гигабайт кэша на медленном диске — это 20–30 секунд до появления окна, а всё
это время на телевизоре чёрный экран с курсором. Страховка в службе браузера:
если `cache2` больше 400 МБ при запуске, он удаляется.

## Сеть

Приставка стоит между домашней сетью и телевизором: телевизор подключён
проводом в отдельный порт приставки и выходит в сеть через неё.

- порт в телевизор — отдельный интерфейс со своим адресом, телевизор получает адрес из той же подсети;
- на обоих интерфейсах должен быть включён `proxy_arp` — **по интерфейсам**, общей настройкой
  он не раздаётся, и без этого телевизор пропадает из сети после перезагрузки
  (`/etc/sysctl.d/90-tv-proxyarp.conf`);
- чип Intel `e1000e` под нагрузкой склонен к зависанию; признак — пульт молчит и
  телевизор не отвечает по сети; лечится сбросом линка (`ip link set … down/up`),
  чем и занимается `stb-nic-watch`;
- пакет пробуждения, пришедший на беспроводной адрес телевизора, пересобирается на
  проводной адрес: адрес получателя записан внутри пакета, простой пересылкой байтов
  дело не решается.

## Графическая сессия

Автовход пользователя, оконный менеджер openbox, окно браузера без рамки и
развёрнутое на весь экран. Курсор увеличенного размера (тема Adwaita, 64) —
тонкий указатель не виден на тёмном фоне.

## Правки вне `/opt/stb`

Помимо каталога приставки система требует нескольких файлов. Копии всех них лежат
в `/opt/stb/system` — пути внутри повторяют настоящие, поэтому установка сводится
к копированию дерева в корень (`README.md` рядом).

| путь | зачем |
|---|---|
| `/etc/systemd/system/stb.target` | единая цель комплекса: `stb-tv-link`, `stb-watch`, `stb-wifi-remote` и остальные юниты с `PartOf=stb.target` — старт и перезапуск одной командой |
| `/etc/systemd/system/stb-nic-tune.service` | `ethtool` для чипа `e1000e`: tso/gso off, eee off, rx 512, wol gub |
| `/etc/systemd/system/stb-nic-watch.service`, `.timer` | проверка зависаний сетевого чипа каждые две минуты |
| `/etc/systemd/system/stb-watch.service` | одна программа на четыре сторожа: телевизор, звук, WoL, кнопка корпуса |
| `/etc/systemd/system/stb-tv-boot.service` | при загрузке включает телевизор и вход приставки |
| `/etc/tmpfiles.d/stb.conf` | каталог `/run/stb` (0775, пользователь приставки): режим, флаги, состояние телевизора |
| `/etc/sysctl.d/90-tv-proxyarp.conf` | `ip_forward` и `proxy_arp` по интерфейсам |
| `/etc/systemd/logind.conf.d/10-powerkey.conf` | кнопка корпуса: короткое нажатие игнорируется, долгое — выключение |
| `/etc/lightdm/lightdm.conf.d/50-stb.conf` | автовход пользователя приставки, сессия `stb` |
| `/etc/bluetooth/main.conf` | имя `home-tvbox1-bt`, `FastConnectable = true` |
| `/etc/NetworkManager/conf.d/wifi-no-rand-mac.conf` | без случайного MAC при сканировании сети |
| `/etc/stb/config` | символическая ссылка на `/opt/stb/config/stb.conf` |
| `/usr/local/bin/tv` | символическая ссылка на `/opt/stb/bin/tv`: единственная команда, общая для всех |

Службы пользователя (`stb-browser`, `stb-web`, `stb-screensaver`) лежат не здесь,
а в `~/.config/systemd/user` — их копии в `home/`.

## Связь с телевизором

Телевизором управляет один демон — `stb-tv-link`. Он держит **одно**
постоянное соединение (SSAP) и подписки на состояние питания, выход звука и
текущее приложение; остальные части приставки спрашивают его через сокет
`/run/stb/tv.sock`:

| кто | зачем |
|---|---|
| `stb-wifi-remote` | кнопки, указатель и клики приложения-пульта |
| `stb-watch` (`bt-pointer`) | указатель и кнопки Bluetooth-пульта |
| `stb-watch` (`tv`, `audio`) | состояние питания для гашения и выключения, выход звука |
| `stb`, `stb key` | команды из командной строки и от кнопок |

### Протокол `stb-tv-link`

Сокет `/run/stb/tv.sock`, обмен — одна JSON-строка на запрос, ответ — одна
JSON-строка. Клиент (библиотека `lib/stbtv.py`, класс `TvDaemon`) ждёт ответ
не дольше 6 секунд; демон ограничивает любую команду 10 секундами и
соединение — 8 секундами.

| команда | обязательные поля | что делает |
|---|---|---|
| `state` | — | питание, выход звука, приложение, громкость, mute |
| `key` | `name` | нажатие кнопки: `UP`, `ENTER`, `BACK`, `VOLUMEUP`… |
| `vol` | `level` **или** `dir` | `level` 0–100 — задать громкость; `dir: down` — шаг вниз; иначе шаг вверх |
| `mute` | `on` **или** `state` | включить/выключить звук: `true/false`, `on/off` |
| `input` | `id` | выбрать вход, например `HDMI_3` |
| `app` | `id` | запустить приложение по идентификатору |
| `speaker` | `id` | переключить выход звука |
| `speakers` | — | список выходов звука |
| `power` | `on`/`state` | выключить телевизор; включение — только WoL |
| `move` | `dx`, `dy` | сдвинуть указатель |
| `click` | — | клик |
| `scroll` | `dy` | прокрутка |
| `apps` | — | все приложения телевизора |

Команды выполняются по одной: на телевизор у демона один клиент, и
параллельные запросы на этой модели приводили к обрывам. Каждая команда
ограничена 10 секундами, ожидание очереди — тоже 10 секундами, так что
зависший запрос не блокирует пульт навсегда.

Ответ всегда содержит `ok`. При ошибке — `{"ok": false, "msg": "..."}`;
демон при этом сбрасывает соединение и подключается заново на следующем
запросе.

Состояние хранится в памяти демона и содержит поле `updated` — время
(в секундах эпохи), когда телевизор подтвердил его в последний раз.
События телевизора обновляют состояние сами; если подписка молчит, `updated`
не двигается, и по нему видно, что данные устарели. Сторож принимает решения
по `power` и не полагается на «свежесть по умолчанию».

### Выбор входа поднимает телевизор

Проверено на 49UK6450: команда `set_input` (её посылает `stb live` и
переключение на приставку) выводит телевизор из ждущего режима. Поэтому
`stb live` включает телевизор, даже если он был выключен, а `stb mode nuc`
сам по себе — нет.

Нажатие проходит за 40–70 мс. Раньше каждая кнопка поднимала отдельный процесс
Python с WebSocket-рукопожатием — 0.5–1.5 с и постоянная нагрузка.
Если демон не отвечает, `tv` работает по-старому, напрямую.

## Модули

Приёмник пульта (`bin/stb-wifi-remote`) вынес всё, что можно проверить
отдельно, в библиотеку:

| модуль | что внутри |
|---|---|
| `lib/stbws.py` | кадры WebSocket: рукопожатие, сборка ответа, чтение от клиента |
| `lib/stbtext.py` | буфер текста: кумулятивная диктовка, повторы, удаления |
| `lib/stbpointer.py` | указатель: копит движение, отправляет 25 раз в секунду |
| `lib/stbback.py` | логика Back: склейка дублей и двойное нажатие |
| `lib/stbkeys.py` | таблица «кнопка → команда демона» для режима телевизора |
| `lib/stbtv.py` | клиент демона телевизора |
| `lib/stbx11.py` | указатель на экране через XTest, без запуска процессов |

В режиме телевизора кнопки идут прямо в демон (без `stb key`);
Power и возврат на приставку остаются в диспетчере — там нужна логика.

## Сторожа

Вся фоновая работа — одна программа `stb-watch` с восемью разделами:

| раздел | что делает | журнал |
|---|---|---|
| `tv` | состояние телевизора: включён — поднять интерфейс, выключен — погасить, долго выключен — выключить приставку | `tvwatch.log` |
| `audio` | держит выход звука по настройке | `audio.log` |
| `wol` | повторяет пакеты пробуждения в провод телевизора | `wol.log` |
| `chassis` | кнопка на корпусе: короткое нажатие выключает приставку | `system.log` |
| `bt-agent` | сопряжение Bluetooth-пульта, только в открытом окне | `pair.log` |
| `bt-keys` | редкие клавиши пульта: раскладка, переключение режима | `extrakeys.log` |
| `bt-pointer` | тачпад пульта превращает в курсор телевизора | `pointer.log` |
| `bt-log` | журнал нажатий Bluetooth-пульта для диагностики | `buttons.log` |

`stb-watch all` поднимает все разделы потоками внутри одного процесса: падение
одного не мешает остальным, каждый поднимается сам. Для отладки любой раздел
запускается отдельно — `stb-watch tv`, `stb-watch bt-pointer` — и пишет в тот же
журнал.

Весь комплекс — три процесса: `stb-watch` (фоновая работа), `stb-tv-link`
(одно постоянное соединение с телевизором) и `stb-wifi-remote` (приёмник
пульта). Рядом живут пользовательские `stb-web`, `stb-browser` и сторож
заставки — они в графической сессии.

## Сборка дистрибутива

```sh
sudo /opt/stb/makedist.sh                    обновить system/ и home/ из живой системы
sudo /opt/stb/makedist.sh /tmp/stb.tar.gz    то же и упаковать
sudo /opt/stb/makedist.sh --to-misc          упаковать и положить на misc
```

Перед упаковкой прогоняются тесты и `install.sh --check`: если что-то красное,
архив не собирается.

Ключ доступа к телевизору (`~/.aiopylgtv.sqlite`) — секрет. В архив он **не
попадает**: после установки телевизор один раз спросит подтверждение. Нужен
готовый ключ в архиве — `--with-key`. В git он тоже не хранится (`.gitignore`).

## Тесты

Каталог `tests/` — pytest-набор без телевизора и X: парсеры, кадры WebSocket,
буфер текста, логика Back, разбор аргументов, согласованность конфига и карт
кнопок, поиск хардкода. Запуск: `sudo /opt/stb/tests/run_tests.sh`
(там же pyflakes и shellcheck).

`tests/fake_tv.py` — поддельный демон телевизора; `tests/bench_consumers.py`
показывает на нём, сколько запросов, CPU и процессов тратят сторожа.

## Проверка состояния

```sh
sudo stb ctl status     # таблица служб: запущена, включена
cat /run/stb/mode                    # текущий режим: nuc или tv
tail -5 /var/log/stb/keys.log        # последние нажатия
```

## Управление без клавиатуры

Если графическая сессия работает, ввод можно подать в активное окно.

```sh
E='env DISPLAY=:0 XAUTHORITY=/home/USER/.Xauthority HOME=/home/USER'

sudo -u USER $E xdotool type --delay 60 'текст'   # напечатать
sudo -u USER $E xdotool key Return                # нажать клавишу
sudo -u USER $E xdotool mousemove 960 620 click 1 # клик по координатам
sudo -u USER $E xdotool getactivewindow getwindowname  # что в фокусе
```
