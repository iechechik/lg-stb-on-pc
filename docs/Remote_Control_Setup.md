# Настройка пульта: Wi-Fi и Bluetooth

Реализована работа с двумя типами пультов - BT и WiFi, последний реализован корректнее, так как BT приложение не имело достаточных возможностей.
Корреляция между состояниями комплекса при одновременном использовании BT и WiFi не учитывалась и не изучалась, предполагается что пульт или\или.

Файлы:

| | карта кнопок Wi-Fi | `/opt/stb/config/buttons-wifi.conf` |
| | карта кнопок Bluetooth | `/opt/stb/config/buttons-bt.conf` |
| | выполнение действий кнопок | `stb key` |
| | приёмник кнопок Wi-Fi | `/opt/stb/bin/stb-wifi-remote`, служба `stb-wifi-remote` |
| | генератор действий кнопок  Bluetooth | `/opt/stb/bin/stb keys apply bt` |
| | журнал приёма Wi-Fi | `/var/log/stb/faketv.log` |
| | журнал нажатий | `/var/log/stb/keys.log` |
| | журнал сопряжения | `/var/log/stb/pair.log` |

Общие параметры (адреса, имена, пороги) — `/opt/stb/config/stb.conf`.

## 1. Канал Wi-Fi (основной)

Приложение: «AirMouse — Smart TV Remote», SAASWISE LTD, пакет `app.airmouse.android`.
https://play.google.com/store/apps/details?id=app.airmouse.android

Механика: приложение ищет в сети телевизоры LG. Коробка отвечает на поиск (SSDP, порт 1900) и принимает соединение на порту 3000, 
поэтому для телефона она выглядит как телевизор. По этому соединению приходят кнопки, указатель, прокрутка и текст клавиатуры.

Подключение: Телефон и коробка в одной сети. В приложении — поиск устройства stb.

Формат карты `buttons-wifi.conf`: `ИМЯ_КНОПКИ=ДЕЙСТВИЕ`.
Слева — имя кнопки в протоколе LG (`ENTER`, `UP`, `DOWN`, `LEFT`, `RIGHT`, `BACK`,
`HOME`, `MENU`, `VOLUMEUP`, `VOLUMEDOWN`, `MUTE`, `CHANNELUP`, `CHANNELDOWN`,
`PLAY`, `PAUSE`, `REWIND`, `FASTFORWARD`, `RED`, `GREEN`, `YELLOW`, `BLUE`,
`INFO`, `GUIDE`, `CC`, `EXIT`, `SUBTITLE`).
Справа — действие из `stb key` (перечень в разделе 3).

Применение: `sudo /opt/stb/bin/stb keys apply wifi` (перезапускает приёмник).

Особенности канала:

- Power управляет только телевизором. Состояние определяется опросом сети, поэтому одно и то же нажатие включает и выключает.
- Приложение присылает событие кнопки дважды на одно нажатие. Приёмник отбрасывает повтор в пределах 0.1 с (`DUP_GAP`). У Back своя склейка (`BACK_DUP_GAP`), потому что второй Back — это команда, а не дубль.
- Два Back в пределах `DOUBLE_BACK` (1.0 с) значат «я вернусь». В приложении: окно прячется, процесс живёт, на экране сетка. В режиме телевизора: возврат на приставку. Одиночный Back всегда отдаётся тому, чем занят экран — браузеру, плееру, телевизору.
- Двойной клик в сетке склеивается в один (`CLICK_GAP`, 0.35 с). В приложениях (Sonarr, Jellyfin) двойной клик остаётся двойным.
- Точпад присылает движение редкими крупными шагами, поэтому шаг делится на `POINTER_SPEED` (0.35). Клик сначала применяет накопленное движение: без этого нажатие уходило по прежнему месту указателя.

## 2. Канал Bluetooth (запасной)

Механика: коробка представляется телефону обычной Bluetooth-клавиатурой и мышью.
Приложение присылает коды клавиш в X-сервер, `xbindkeys` превращает их в действия
`stb key`. Коробка видна как `home-tvbox1-bt`.

Сопряжение, обычный способ:

```sh
sudo stb pair 180        # окно 180 секунд; то же делает плитка «Добавить пульт»
```

На телефоне: настройки Bluetooth → подтвердить код.
Результат проверяется командой:

```sh
stb pair --list          # что сопряжено и что подключено сейчас
```

Сопряжение, если обычный способ не проходит (агент не отвечает): три окна
параллельно — телефон ищет только при открытых окнах 1 и 2.

```sh
# окно 1: адаптер готов
sudo bluetoothctl power on
sudo bluetoothctl pairable on
sudo bluetoothctl discoverable on
sudo bluetoothctl discoverable-timeout 0

# окно 2: агент, подтверждающий код (висит до Ctrl+C)
while :; do echo yes; sleep 1; done | sudo bluetoothctl --agent=DisplayYesNo

# окно 3: наблюдение
sudo journalctl -u bluetooth -f
```

После сопряжения — пометить доверенным, чтобы подключался сам:

```sh
sudo bluetoothctl devices                       # найти пульт, взять MAC
sudo bluetoothctl trust AA:BB:CC:DD:EE:FF
sudo bluetoothctl connect AA:BB:CC:DD:EE:FF
sudo bluetoothctl info AA:BB:CC:DD:EE:FF | grep -E "Paired|Trusted|Connected"
```

Ожидается `Paired: yes` и `Trusted: yes`.

Если телефон пишет «не удалось» повторно:

1. На телефоне выключить и включить Bluetooth.
2. На коробке убрать остаток сопряжения: `sudo bluetoothctl remove AA:BB:CC:DD:EE:FF`.
3. Повторить окна 1–2.

Формат карты `buttons-bt.conf`: `X-КЛАВИША=ДЕЙСТВИЕ`.
Имя клавиши, которую присылает телефон, определяется командой `xbindkeys -k`
(нажать кнопку на пульте — в выводе будет имя).

Применение: `sudo /opt/stb/bin/stb keys apply bt` — пересобирает `~/.xbindkeysrc` из карты и
перезапускает `xbindkeys`. Проверка без записи: `sudo /opt/stb/bin/stb keys apply bt --dry-run`.

Что доходит в BT-режиме (проверено):

| Кнопка | Код evdev | Имя клавиши в X | Действие |
|---|---|---|---|
| Громкость + | KEY_VOLUMEUP 115 | XF86AudioRaiseVolume | volup |
| Громкость − | KEY_VOLUMEDOWN 114 | XF86AudioLowerVolume | voldown |
| Mute | KEY_MUTE 113 | XF86AudioMute | mute |
| Back | KEY_BACK 158 | XF86Back | back |
| Home | KEY_HOMEPAGE 172 | XF86HomePage | home |
| Menu | KEY_MENU 139 | XF86MenuKB | menu |
| Play/Pause | KEY_PLAYPAUSE 164 | XF86AudioPlay | playkey |
| Перемотка назад | KEY_REWIND 168 | XF86AudioRewind | prev |
| Перемотка вперёд | KEY_FASTFORWARD 208 | XF86AudioForward | next |

Чего в BT-режиме нет: стрелок (приложение присылает только движение мыши) и нажатия
ОК (BTN_LEFT не приходит). Выбор делается как «навести курсор + Play/Pause» —
эта кнопка нажимает то, что под указателем.

Ограничения канала:

- соединение существует, только пока приложение открыто на экране телефона;
- после первого подключения `bluetoothd` может упасть (SIGSEGV в HID-модуле),
  в журнале — `hidp_recv_intr_data(): BT socket read error: Bad file descriptor`.
  Лечится `sudo systemctl restart bluetooth`, повторное подключение проходит;
- канал требует работающей графической сессии (вход выполняется автоматически).

## 3. Действия кнопок

Общий перечень действий `stb key` (полный список — `stb help key`):

```
power  volup  voldown  mute  back  home  menu  ok
up  down  left  right  chup  chdown
red  green  yellow  blue  info  guide  cc  exit
prev  play  playkey  pausekey  next  tobox
```

Действия делятся по текущему режиму — приставка (`nuc`) или телевизор (`tv`).
Режим хранится в `/run/stb/mode`, меняется плиткой «На телевизор», командой
`stb mode` или кнопкой ⚙ на BT-пульте.

Различие режимов на примере:

| Действие | Режим приставки | Режим телевизора |
|---|---|---|
| `back` | приложению; двойной — спрятать и на сетку | Back в телевизор; двойной — на приставку |
| `home` | в приложении — убрать всё и на сетку; на сетке — то же | меню источников телевизора |
| `up` / `down` | выбор плитки; вне сетки — прокрутка страницы | стрелка в телевизор |
| `ok` | Enter: на сетке — выбранная плитка, в приложении — прежний фокус | Enter в телевизор |
| `playkey` / `pausekey` | нажатие под указателем; на сетке — запуск выбранной плитки | Play / Pause телевизора |

## 4. Если кнопка не работает

Проверять по порядку, каждая строка отсекает половину причин:

1. Режим: `cat /run/stb/mode` — кнопки могут уходить в другой канал.
2. Дошло ли нажатие: `tail -5 /var/log/stb/keys.log`.
3. Дошло ли до коробки: Wi-Fi — `tail -5 /var/log/stb/faketv.log`;
   Bluetooth — `xbindkeys -k`.
4. После правки карты: Wi-Fi — `sudo /opt/stb/bin/stb keys apply wifi`,
   Bluetooth — `sudo /opt/stb/bin/stb keys apply bt`.

## 5. Правила правки карт

- Комментарий — только отдельной строкой, начиная с `#`. Комментарий в конце
  строки попадёт в само действие и сломает его.
- Пустые строки игнорируются.
- Неизвестное действие не мешает остальным кнопкам: строка просто ничего не делает.

## 6. Приложение-пульт: режимы и ввод текста

Приложение работает в трёх режимах: **Пульт** (только кнопки), **Точпад** (палец
двигает курсор), **Мышь** (курсор двигает наклон телефона).

Что важно знать:

- В режиме точпада приложение не присылает нажатий — ни по Wi-Fi, ни по Bluetooth
  (в журнале видны только `PLAY`/`PAUSE`). Поэтому выбор делается приёмом «навести
  курсор + кнопка Play/Pause»: она нажимает то, что под указателем.
- Соединение живёт, только пока приложение открыто на экране телефона; уход в фон
  разрывает связь.
- Тип устройства: телефон отдаёт два устройства — клавиатуру (кнопки) и мышь
  (движение и кнопки мыши).

**Ввод текста.** Распознавание речи идёт на телефоне, оттуда текст приходит в
приставку по одному символу. Если печатать каждый символ отдельной командой,
быстрые страницы теряют часть букв, поэтому приёмник собирает символы в буфер
(0.35 с) и печатает строку целиком. Параметр буфера — `TextBuffer` в приёмнике.
В режиме телевизора текст уходит во внутреннюю службу ввода телевизора.

## Словарь

**Служба (демон)** — программа, которая работает в фоне и запускается системой.
**Карта кнопок** — текстовый файл, где написано, какая кнопка что делает.
**Режим** — состояние «пульт управляет приставкой» или «пульт управляет телевизором».
**SSDP** — протокол поиска устройств в локальной сети; по нему приложение находит телевизор.
**xbindkeys** — программа, которая превращает нажатия клавиш X-сервера в команды.
**HID** — стандартный профиль Bluetooth-устройств ввода (клавиатура, мышь).
